# Техническая спецификация — v0.1.0

[English](SPEC.en.md)

## Цель и границы

Определять, какие **потенциально бесплатные по названию** модели OpenCode отвечают на короткий запрос при текущих подключениях пользователя, не меняя настройки OpenCode. Это экспресс-проверка, **не** аудит биллинга, не полноценный бенчмарк, не объединитель квот и не fallback-плагин.

## Архитектура

- `src/core.mjs` — чистая логика отбора моделей, чтения событий, статусов и отчётов.
- `src/cli.mjs` — интерфейс командной строки и запуск процессов.
- `config/approved-models.json` — дополнительные модели, вручную разрешённые пользователем.
- `launchers/` — запускатели для трёх ОС, использующие общий движок Node.js.
- `tests/` — офлайн-тесты и заглушка OpenCode CLI.

## Функциональные требования

1. Получать ID через `opencode models`, исключать дубли и некорректные строки.
2. По умолчанию выбирать только `opencode/*-free`, `openrouter/*:free` и `openrouter/openrouter/free`. Для прочих моделей требовать явного разрешения, а не делать вывод о цене по названию провайдера.
3. Поддерживать точный список моделей, исключение провайдеров, лимит количества, тайм-аут и папку отчётов.
4. По умолчанию показывать предварительный список. Для отправки запросов требовать `--run` и ввод `YES`; `--yes` — только осознанная автоматизация.
5. Последовательно выполнять `opencode run --standalone --archived --model <id> --format json` во временной папке с коротким постоянным тестовым текстом.
6. В дочернем процессе устанавливать `OPENCODE_PURE=1` и `OPENCODE_CONFIG_CONTENT`, пытаясь выключить плагины и все инструменты. Это защита **по возможности**, не гарантия для любых расширений. Пользовательские настройки не изменять.
7. Разбирать JSON Lines: текст, ошибки, фактический ID. Ставить `OK` только при наличии контрольной фразы **и** совпадающем ID отвечавшей модели. При отсутствии ID — `REPLY_UNVERIFIED`.
8. Различать `REGION`, `AUTH`, `BILLING`, `QUOTA`, `MODEL_UNAVAILABLE`, `TIMEOUT`, `ERROR`, `MODEL_MISMATCH`, `NO_REPLY`, `REPLIED_OTHER`, `REPLY_UNVERIFIED`.
9. Создавать отчёты CSV/JSON в локальной исключённой из Git папке. Сокращать и маскировать типовые секреты в ошибках и нейтрализовать формулы таблиц в CSV.
10. Удалять временную папку после проверки; архивные сессии OpenCode могут оставаться.

## Нефункциональные требования

- Node.js 20+, без внешних npm-зависимостей в рабочем коде.
- Запускатели macOS/Linux/Windows и автоматические офлайн-тесты на всех трёх системах.
- Настоящие запросы только после явного выбора `--run` (команда каталога `opencode models` сама может обновить список из сети).
- Никаких обещаний гарантированной бесплатности: тарифы задаёт провайдер, общие лимиты действуют независимо от модели.
- Один короткий ответ не подтверждает качество программирования, вызов инструментов или будущую доступность.

## Ограничения и планы

- Нужны Node.js и OpenCode CLI — готовые автономные `.exe`/`.app` пока не распространяются.
- Слово `free` — эвристика, не проверка цен по API провайдера.
- Не все версии OpenCode передают ID отвечавшей модели; тогда вердикт только `REPLY_UNVERIFIED`.
- В CLI могут быть модели, скрытые в Desktop.
- Изоляция плагинов зависит от версии OpenCode и не является песочницей безопасности.
- В будущем возможны официальная проверка цен и лимиты бюджета, но **в v0.1.0 этого нет**.

## Критерии приёмки

- Просмотр выводит кандидатов и не вызывает `opencode run`.
- Подтверждённый тест создаёт оба формата отчёта и статусы по каждой модели.
- Правильный ответ с совпавшими метаданными — `OK`; без них — `REPLY_UNVERIFIED`; другой ID — `MODEL_MISMATCH`.
- Ошибки квоты, ключа, региона, биллинга и тайм-аута распознаются на имитированных данных.
- Автоматические тесты обходятся без реальных API и оплаты.
